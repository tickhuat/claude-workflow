### #49 — `is_in_rebase()` doesn't handle worktrees

```
Context: claude-workflow framework. Bug to fix: issue #49.

Problem: src/claude_workflow/lib/git_utils.py:35-38 checks
`cwd/.git/rebase-merge` and `cwd/.git/rebase-apply`. Inside a git worktree,
.git is a *file* (gitdir pointer), not a directory — so the path checks
always return False. Pre-existing bug; just fixed #13 made post_bash
reliably pass a worktree path here, exposing it.

Effect: commit-deviation enforcement runs during a rebase performed inside
a worktree.

Workflow:
1. Skill(using-superpowers) → switch-mode-bugfix.
2. git checkout -b feature/issue-49-is-in-rebase-worktree
3. RED test in tests/scripts/test_git_utils.py:
   - Create a real parent repo + worktree (use the `_git()` helper pattern
     from tests/scripts/test_state.py:633 — it's a copy-able snippet).
   - Start a rebase in the worktree (e.g. add commit, then
     `git rebase -i HEAD~1` with GIT_SEQUENCE_EDITOR=true to make it
     non-interactive — or `git rebase -X ours HEAD~1`).
   - Assert `is_in_rebase(worktree_path)` returns True.
   - Cleanup: git rebase --abort.
4. Verify RED.
5. GREEN: rewrite is_in_rebase to use `git rev-parse --git-dir`:
       def is_in_rebase(cwd: Path) -> bool:
           try:
               r = subprocess.run(
                   ["git", "rev-parse", "--git-dir"],
                   cwd=cwd, capture_output=True, text=True, timeout=2,
               )
           except (FileNotFoundError, subprocess.TimeoutExpired):
               return False
           if r.returncode != 0:
               return False
           git_dir = Path(r.stdout.strip())
           if not git_dir.is_absolute():
               git_dir = (cwd / git_dir).resolve()
           return ((git_dir / "rebase-merge").exists()
                   or (git_dir / "rebase-apply").exists())
6. Verify GREEN + full suite.
7. Commit with closes #49.
8. PR + audit + merge + cleanup.

Gotchas:
- Test must do real `git init` + `git worktree add` + `git rebase`. No mocks.
- `git rebase -i HEAD~1` requires GIT_SEQUENCE_EDITOR; cleaner is `git rebase
  --keep-empty HEAD^^` if there are 2 commits, or just write a state file
  manually at .git/worktrees/<name>/rebase-merge/ to simulate. Pick
  whichever is cheaper to set up reliably.
- Existing test for is_in_rebase (if any) probably uses the regular-repo
  case — keep that test passing too.

Report back: PR URL.
```
